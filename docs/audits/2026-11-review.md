3. pipeline/research/spend-guard.js:`load()` returns `{}` on a corrupt/missing ledger, so counters reset (fail-open on corruption; same pre-existing pattern as the grounded guard). Read-modify-write on the ledger is not locked across concurrent processes, so caps can be exceeded slightly.

6. Default caps (40/day, 15/run per provider) are placeholders, not a confirmed budget.
7. CI (.github/workflows/ci.yml) is untested on GitHub; it runs on every PR and on cloud/** pushes, and `npm ci` in site/ needs the lockfile to be in sync.
