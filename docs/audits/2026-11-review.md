### Issues
1. **Medium (fixed here)** social/lib.js:72 `stuckIgPublishes`: `stuckAlertedAt` survived a reset. `claimIgPublish` (lib.js:83) spreads the old `ig` object, so after a human resets a stuck draft to `queued` and it gets stuck again, the alert would never fire again. 3. **Low** spend-guard.js:94-100 vs 102: check and record are separate lock sections. Overlapping processes can each pass `checkProvider` at cap−1 and overshoot by roughly the number of concurrent processes. Counts are no longer lost (7c8dec0), but a strict cap would need check+record inside one lock. Not changed.
4. **Low** spend-guard.js:62 ledger stale-lock break uses `rmdir` (non-atomic). Already acknowledged in the fix log; holds last milliseconds.
5. **Low** social/lib.js `breakStaleLock`: if the lock is re-taken between rename and `linkSync`, the link fails and the fresh lock file is unlinked. That needs a lock that is >20 min stale plus a sub-millisecond race. Acceptable.
